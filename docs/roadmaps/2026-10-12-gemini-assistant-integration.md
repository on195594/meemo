## 1. 基线与目标

建议分期：首批交付只读三工具；新建/修改仍是完整方案目标，但在确认模型与幂等契约收敛前不注册写工具、不申请写 scope。此为方案建议，不将用户目标擅自缩减成永远只读。

用户已确认 travel-cards 的真实 Gemini 网页/手机双端验收完成。参考本机 `/home/lin/travel-cards/docs/roadmaps/ai-client-integration.md` 与 `src/lib/mcp/`，不再把其客户端兼容性列为 pending。该结论来自用户，不是本轮重测；图片上传等专项不因此自动通过。

Meemo 目标：在 Gemini 网页/手机中搜索、读取和保存私人笔记，不在 Meemo 内置聊天界面。沿用 travel-cards 的 MCP + OAuth 路线；Meemo 不持有 Gemini API Key。Google 的账号/地区资格可能变化，参考项目成功不代表所有账号可用，也不代替 Meemo 自身验收。本次不重复作未经实测的资格断言。

## 2. 架构与边界

Gemini → HTTPS `/mcp`（Streamable HTTP）→ 独立 Bearer 认证 → 应用服务 → MongoDB。

- 保留 Express/CommonJS 单体及现有分层，不独立部署网关，不复制 Next.js/Mongoose 实现，不抽跨项目框架。
- `src/http/` 承担协议、OAuth 路由、请求校验和认证；`src/services/` 承担工具行为与授权；`src/database/` 承担客户端、授权、令牌持久化。
- 笔记操作复用 `thing-service.js`、`search-service.js` 和现有数据库层；禁止从 transport 直连集合。
- 浏览器 REST 保持 Session 认证，不将 MCP Bearer 扩散到全部 API。发现与 OAuth 路由在 SPA fallback 前注册，普通笔记功能不依赖 MCP 可用。
- 首版无附件读写、图片、删除、公开分享、批量修改、导入导出、账户设置、语义检索、自动后台任务。
- MCP 可引入官方协议 SDK；OAuth 优先复用经审查的成熟实现。实施前验证 CommonJS/Node 兼容性、维护状态与锁文件影响，不盲搬参考项目依赖，也不手写密码学。

## 3. 工具与数据契约

| 工具 | scope | 受限输入与输出 |
| --- | --- | --- |
| `search_notes` | `notes.read` | 查询、现有搜索模式、分页；只返回 ID、版本和短摘要 |
| `get_note` | `notes.read` | 笔记 ID；返回正文、版本，不返回 richContent、附件下载地址或内部元数据 |
| `list_tags` | `notes.read` | 返回当前用户已有标签，分页和数量上限；需扩展现有聚合接口 |
| `create_note` | `notes.create` | 正文；创建私有笔记，返回 ID、版本 |
| `update_note` | `notes.update` | ID、正文、必填 expectedRevision；返回新版本 |

- 服务端从令牌解析 userId；工具不接受 ownerId，也不暴露数据库查询对象。每次搜索、读取、更新都校验所有权，不能调用公开分享读取分支绕过权限。
- 首版搜索只查未删除、未归档笔记；已归档可否读取须在工具描述中明确：按 ID 可读取本人未删除笔记，搜索不含归档。正文和摘要作为不可信数据，不作为指令。
- 显式 schema、字符串长度、结果数、分页深度、响应总大小上限；沿用现有正文校验上限。超限返回可行动错误，不静默截断正文后当成完整内容用于更新。
- 标签复用正文标签提取机制，不新增独立标签写入语义。当前 `thing-service.getTags` → `things.getTagUsage` 在排序后直接 `toArray()`，没有分页；需兼容地增加可选分页参数，通过数据库 `$skip/$limit`（limit + 1 判断 hasMore）限制返回，保留现有 REST 调用语义，不能先全量加载再切片，也不能读历史 `tags` 投影。聚合仍可能扫描该用户全部笔记/标签，用 maxTimeMS 和限流约束成本，分页不保证工作量常数级。标签范围为本人全部未删除笔记（含归档），与默认搜索范围差异须写入工具描述。
- 授权后笔记可被发送给 Google；授权界面说明这是账户级权限，不仅限公开笔记。首版不新增逐笔记 ACL。

## 4. OAuth 与授权生命周期

- 使用授权码 + PKCE S256，单次、短效授权码；绑定用户、客户端、redirect_uri、resource 与 scopes。
- 提供 MCP 所需受保护资源元数据、授权服务器元数据及正确的未认证挑战；具体协议版本与 Gemini 握手在实现阶段锁定并验收。
- 适配 Gemini 客户端注册方式；DCR 只接收严格白名单字段，限制注册速率/数量、回调地址和元数据体积。不抓取客户端提交的外部 URL。回调精确匹配，无通配符、开放重定向或任意内网回调。
- OAuth 登录使用现有账号 Session；同意/撤销操作必须有 CSRF 防护，服务端校验登录用户。读取、新建、修改独立选择，默认仅请求读取；修改需同时授权读取，以支持核对正文和版本。
- 访问令牌绑定受众、用户、客户端、授权及 scope，仅持久化哈希；响应和日志不泄露凭证。采用有限有效期，建议 24 小时；首版不发 refresh token，过期重新连接。此交互必须经真实 Gemini 验收，不以参考项目期限替代决策。
- 持久化分为 client 公共注册元数据、绑定 userId + clientId 的 grant、绑定 grant 的 token。不能假设每个 DCR client_id 只供一个用户使用，也不能假设 Gemini 一定共享 client_id。
- 每次调用检查授权撤销、过期及用户有效性；不只依赖令牌签名。设置页只列当前登录用户的 grant，显示客户端、权限、有效期；撤销按认证用户 ID + grantId 限定，只失效该 grant 的令牌，绝不修改全局 client 状态或影响其他用户。管理级停用客户端不属于用户设置功能，也不在首版范围。需测试同 clientId 的两用户隔离。不承诺撤销能追回已返回内容或回滚已提交写入。
- 明确可信反向代理、固定公开 issuer/resource；不从未验证 Host 构造发现地址。校验 Origin，限制 CORS，不将 Origin 视为用户认证。

## 5. 写入安全

### 更新

先按授权用户读取目标和 revision，验证 expectedRevision 一致，拒绝已删除、公开或共享笔记。只允许修改正文，其余状态（附件、颜色、归档、置顶、分享）从同一已读快照保留，再调用现有 `put`。数据库原子条件继续包括 ownerId、revision、未删除状态；并发改变分享状态也必须递增 revision，实施时验证所有相关写路径。

冲突要求重新读取并重新确认，绝不自动覆盖或自动重试；读检查和数据库 CAS 两者缺一不可。复用现有 URL 提取/富化时保留 SSRF 防护、出站限制及请求期限，鉴权和前置条件检查应在任何富化网络请求之前执行。

### 写阶段门禁：确认模型和失败处理

工具 annotations、模型口头承诺和 Gemini 的弹窗都不能给服务端提供可信的逐次用户确认凭据。本次不声称客户端弹窗能力已核实，也不预先引入待确认集合、Vue 确认页和跨集合恢复状态机。

写阶段开始前需由用户明确选择安全契约：

1. **有限范围持续授权**：用户在 OAuth 同意页明确允许该 scope 内的后续调用直接写入；Gemini 原生确认仅作体验层，不能承诺每次都经人工确认。保留所有权、scope、私有目标限制和 CAS。此模式不是本次默认授权。
2. **强制逐次确认**：必须设计服务端可验证的用户确认机制；另行评估存储模型、撤销、过期、CSRF、失败恢复和复杂度预算，通过设计审查前保持写工具关闭。不能将服务端待确认当成已写入，也不能用提示词取代门禁。

创建幂等同样是未完成的核心层工作：当前 `thing-service.add` / `things.insertFull` 不接受调用方指定 ID，也无业务幂等键索引；不能声称原样复用即支持预分配 ID。建议在服务/仓储层增加专用幂等创建入口，由服务器生成、校验并绑定授权用户的请求标识，使用 `things` 单文档记录操作标识与请求摘要，配合局部唯一索引；普通 REST 创建签名和数据语义不变。具体键范围、重复请求返回、导入/恢复兼容和唯一索引迁移需在写阶段设计中明确并测试，不允许 transport 越层直写，也不强加副本集事务或分布式锁。

超时不等于失败：创建重试仅能使用原幂等标识，同键不同内容拒绝；更新 CAS 冲突后读回核对，不自动覆盖。授权撤销后，即使重放已有请求也必须先拒绝认证；幂等记录不能成为越权读取入口。未落实这些契约前，只读工具可交付，写工具不可上线。

## 6. 运维、错误与审计

- 功能开关默认关闭；实现后仅通过单独授权的配置/部署开启，不借本方案操作生产。
- 用户、客户端、IP 分层限流；请求体、执行时间、并发、输出体积有界；写操作超时仍保留可核查状态，不把 abort 当作数据库回滚。
- 使用 MCP 规范区分协议错误与工具错误；认证失败、scope 不足、找不到/无权访问、版本冲突、操作待确认/过期、结果未知均有稳定语义；待确认/过期状态仅在选择强制逐次确认方案后定义，不是首版接口。不泄露他人笔记是否存在。
- 审计仅含请求/操作 ID、用户标识、工具、笔记 ID、版本、结果和耗时，不含正文、查询词、令牌、授权码、Cookie；反向代理同样脱敏。
- 不开启通用 URL 访问工具；笔记中的恶意指令不能提升 scope 或触发确认以外操作。

## 7. 实施与验收门禁

1. **只读闭环**：OAuth、连接管理、三工具、真实网页/手机发现授权和读笔记。测试跨用户 ID/标签/搜索隔离、回调/PKCE/resource/scope 校验、撤销/过期、限流和输出上限。
2. **受限写入（有前置门禁）**：先确定用户确认契约和核心层幂等设计，再实现两个写工具；覆盖跨用户请求 ID、重试/进程退出恢复、同键异内容、CAS、元数据保留、共享/已删除拒绝、撤销后重放拒绝、未知结果核查。若选择强制逐次确认，另补确认 CSRF、过期/单次消费、撤销后确认拒绝及独立设计审查。
3. **发布准备**：反向代理/发现端点、脱敏、备份恢复与回滚说明；切断 MCP 后普通 Session 功能正常。必须独立授权部署。

代码落地时服务端跑 `npm test`；涉及确认/授权页面跑 build、前端 typecheck 和 Vitest；HTTP 合同变更更新 OpenAPI 与生成类型；API、配置和备份说明分别同步当前文档。不把本方案当成已实现合同。

Meemo 真实双端验收尚未执行：分别记录客户端、日期、部署版本、只读/创建/更新、确认流程与撤销结果，证据不含私密正文和凭证。travel-cards 的成功是参考，不是本项目 PASS。
