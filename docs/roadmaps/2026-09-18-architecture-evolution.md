## 1. 决策摘要

下一阶段不是重构成另一个应用，而是把现有模块化单体变成“可信赖的个人信息工作台”：先可靠保存、验证恢复，再做稳定引用、找回与可选 AI。

维持 Express + CommonJS + Promise-first 服务、Vue 3 + TypeScript + Composable、MongoDB、filesystem-first 附件。保持单个应用部署单元，不增加第二套在线业务数据库、消息队列、常驻 Agent、向量库或全局状态框架。不因为 travel-cards 使用 Next.js 而迁移框架。[M1]

优先级主线：**M0 验证与恢复基线 → M1 写入一致性 → M2 生命周期与简化 / M3 找回质量 → M4 条件式 AI 增强**。这不是所有任务串行等待的审批链：M1 盘点和测试可与 M0 并行；M3 只读基线不依赖回收站或历史代码删除完成。M0、M1 是首批重点；产品新增能力另行批准，不绑定未经估算的日历工期。

## 3. 目标架构

保持既有主边界：

`Vue 页面/组件 → Composable → API Client → HTTP 校验与认证 → Service → MongoDB / Attachment Storage`

`app.js` 与 lifecycle 只承担装配、连接、启动、退出与少量同进程任务。新模块不扩大可变全局状态，但不引入 DI 容器。核心实体仍是 Thing；搜索索引、摘要等只能是可重建派生数据。[M1]

近期只收紧三个边界：

| 边界 | 必须明确的契约 |
| --- | --- |
| 编辑器到持久层 | 哪个版本可被修改、发生冲突后保存什么、何时可以显示“已保存”。 |
| 业务数据到恢复工具 | 哪些数据构成完整备份，镜像/配置/数据库/附件如何匹配，失败如何退出。 |
| 原始笔记到派生能力 | 原文由用户控制，派生物可删除重建，AI 关闭不影响核心读写。 |

### 4.1 恢复范围与失败退出

备份清单必须区分业务数据、派生数据、会话和维护控制状态。`users/things/settings`、附件与必要索引必须可恢复；会话是否恢复、维护 freeze 是否保留/解除要明确处理，不能恢复后因残留维护标志永久不可写，也不能未经核验就解除停写。

不可变备份集中不写临时覆盖文件，不用 `chmod` 解锁后补证据。恢复工作目录使用私有权限；对导出的 Compose、镜像 inspect 和日志先检查并删除凭据值，不能把原始 inspect 输出当成“非敏感元数据”。密钥备份/轮换通过独立受控渠道，不进入 Git 或普通验收附件。

只恢复明确批准的 `meemo` 命名空间与本项目附件，不使用整实例恢复覆盖 `travel_cards`；命名空间参数参考 [M8] 并按实际工具版本验证，共享服务操作见第 11 节。恢复测试必须设置另一数据库的哨兵记录，验证其未变。不得在共享生产卷运行 `down -v`、清空整个实例或把文件恢复挂载指向生产卷。

应用镜像、MongoDB 镜像/版本、数据库工具版本均记录。合成数据演练只能证明流程；生产恢复就绪仍需批准后的真实备份可读性、数据范围与抽样字节验证。恢复旧备份后要使旧会话失效，并要求客户端重新认证、读回基线后再处理本地草稿，不能重放恢复前的保存队列。

**代码退出门槛：** 完整验证与合成数据隔离恢复通过并留证；M1 盘点可提前并行。

**生产退出门槛：** 核对真实数据/附件备份集及回退路径后，才允许本轮受控切换。未获授权记为 `BLOCKED_AUTH`，不是“恢复已通过”。

## 5. M1：从“原子写入”走向“不会静默覆盖”

**目标：一个旧客户端、一个晚到请求，不能悄悄覆盖更新的笔记。**

### 5.1 单文档版本契约

新增由服务端管理的正整数 `revision`，限制在 JavaScript 安全整数范围，溢出时拒绝写入而不回绕。新建从 1 开始，修改和删除携带 `expectedRevision`；更新使用 `_id + ownerId + revision` 条件，并在同一原子操作中递增。MongoDB 支持预期值过滤的单文档条件更新；本方案不把它扩展为跨文档事务保证。[M7]

拟定 HTTP 契约：可访问对象版本不匹配返回 `409 REVISION_CONFLICT`；缺少必需 `expectedRevision` 返回 `428 PRECONDITION_REQUIRED`；非法类型/范围沿用 400 校验错误；对象不存在或不属于当前用户保持相同的 404 行为。先完成认证，任何冲突查询也必须包含 owner 条件。错误映射、OpenAPI 和客户端在同一变更中落地，不按错误文案推断类型。删除成功沿用既有成功响应，不为永久删除伪造“下一版本”。以上新增错误码先写入并确认接口契约。

禁止只在服务层先读一次 revision，再无条件写入；最终数据库写条件必须包含版本。禁止长期保留“不传 revision 就允许覆盖”的兼容旁路。

**基线绑定规则：** `baseContent + baseRevision` 来自编辑器打开/确认合并时的同一个完整快照。列表后台刷新到较新 revision 时，不得把该 revision 嫁接给尚未合并的旧草稿，否则旧正文会借用新版本号覆盖服务端。

| 写路径 | 条件和版本规则 |
| --- | --- |
| 正文、颜色、分享/公开、归档、置顶、附件引用 | 用户命令基于同一快照；任何实际 Thing 字段变更均条件更新并递增 revision。新代码优先提交必要字段；沿用全量 PUT 时必须证明正文与版本同源。 |
| 永久删除 | `_id + ownerId + expectedRevision` 原子删除；不先查后无条件删。不存在和冲突分别处理，不盲目重放。 |
| 新建/新建式导入 | 由目标实例分配 ID/初始版本；定义重复导入策略。不得伪装成“更新已有笔记”。 |
| 合并式导入 | 若确有覆盖既有笔记的分支，必须明确冲突策略；未定义前禁止无条件覆盖。 |
| 在线维护修复 Thing | 使用读取的版本及必要内容条件做 CAS，成功变更后递增；失败跳过或重新读取计算，不能拿旧结果配新版本重试。 |
| 离线迁移/完整灾备恢复 | 在所有写者停止并排空后执行；遵循迁移/恢复版本策略，不伪装成普通 HTTP 调用。 |
| 仅重建 tags 等投影 | 不更改 Thing 时不递增 Thing revision；投影不能变成第二事实源。 |

### 5.3 草稿、命令与网络不确定性

同一笔记用 `baseSnapshot / draft / inFlightSnapshot / draftGeneration` 等轻量状态表达，不要求建立新的持久操作平台。成功回包只推进对应快照；有更新的本地输入时保留草稿，并在确认仍基于本次成功写入后继续保存。

有未保存正文时，归档、置顶、颜色等命令要么和该草稿形成同一请求快照，要么等待保存完成；若选择独立字段命令，必须显式处理后续草稿的基线，不得默默替换正文。删除时必须处理未保存草稿，成功删除后取消该笔记后续队列，不能由迟到请求重建笔记。

读回内容与发送快照相同，可确认“目标状态已存在”，但不能证明是哪一次网络请求写成；读回冲突或身份变化时保留草稿并提示。首次创建无已知 ID、或删除返回丢失时，不自动通过内容匹配重试创建/删除，不承诺 exactly-once；用户核对列表/详情后决定。切换账号时销毁原账号队列及订阅，旧响应不能更新新账号。

### 5.4 数据迁移与回退

先盘点旧客户端与外部 API 调用者。不存在必须长期支持的旧客户端时，用一次受控停写切换，避免引入平行 API 版本。确有旧调用者时另行确定兼容退出时间，不默认永久兼容。

迁移只补齐缺失 revision 的旧文档；发现非法版本值时阻止切换并输出脱敏统计。脚本必须 dry-run、绑定精确目标数据库与已识别实例、可重复执行。不得以 `$set revision: 1` 重置全库。新建式导入分配目标初始版本；灾备数据保留归档中的版本，并执行会话失效/客户端重新读基线策略。导出格式记录 schema/兼容规则，不把 revision 当作跨实例全局版本。

**一次切换的顺序：** 核对授权与恢复集 → 阻止新写请求 → 停止应用/Worker/脚本并排空在途写 → 备份并验证 → dry-run/迁移/复核 → 启动配套前后端镜像、暂不开放外部写 → 验证旧请求拒写和新流程 → 开放。停写与备份的具体操作沿用经修订的 runbook，不通过公开健康接口执行迁移。

源码的 `checkNotFrozen()` 与最终写入不是一个原子操作，故 `acquireWriteFreeze()` **不等于所有在途写已经排空**。[M2] 切换不能仅置位 freeze 后立即 dump；应停应用写者并完成排空验证。只操作 Meemo Web 不需要停 travel-cards；涉及共享 MongoDB 实例/卷时必须按第 11 节协调两个应用。

**回退风险：** 旧服务端不知道 revision，即使数据结构能读取，也可能重新开放无条件写。回退必须使用仍支持版本保护的已验证镜像，或在停写/只读状态恢复匹配备份；禁止带写流量直接回退到不保护版本的二进制。

### 5.5 必须通过的对抗测试

| 测试编号 | 必须验证的反例 |
| --- | --- |
| M-AT-01 | 两个不同写入使用同一版本竞争，恰有一个成功、另一个 409；失败草稿仍在。 |
| M-AT-02 | 保存 A 在途输入 B；A 回包不清空 B，不把 B 显示为已保存。 |
| M-AT-03 | 旧草稿基于 v10，列表刷新到 v11；提交仍不得借用 v11。 |
| M-AT-04 | 正文、置顶/归档、分享、颜色、附件同时操作；逐个证明正文不被旁路覆盖。 |
| M-AT-05 | 删除与保存竞争、创建回包丢失；不自动重复创建、不复活已删除笔记。 |
| M-AT-06 | 缺版本、非法版本、其他 owner、过期 Session、账号切换；分别拒绝且无对象信息泄露。 |
| M-AT-07 | 维护修复与编辑竞争、导入分支；条件更新和版本规则没有旁路。 |
| M-AT-08 | 迁移重复执行不重置有效版本；伪造目标库/资源标识时停止；freeze 后在途写未排空时不开始备份。 |
| M-AT-09 | 旧客户端在新服务端被拒写；回退镜像、会话失效与共享库哨兵联合验证。 |

接口响应契约以真实数据库集成测试验证；编辑次序使用可控制回包时序的现有前端测试验证。固定 sleep 的“看起来没有冲突”不是并发证明。

**代码退出门槛：** M-AT-01～09 中可隔离运行的用例及全部枚举写路径通过；前后端构建一体检查。**生产门槛：** 授权、真实备份、排空与旧客户端策略到位；NOTE-CAS 和 EDITOR-SAVE-STATE 可以分提交，但不能分批独立发布。

## 6. M2：生命周期闭环与历史复杂度退役

**目标：从“保存安全”继续收口到“能引用、能撤销、能恢复”。**

| 编号 | 任务 | 验收标准 |
| --- | --- | --- |
| M2-01 | 核对并补齐稳定的私有笔记直达链接。 | 链接以稳定 ID 识别笔记；重命名、列表排序或筛选不破坏引用；没有权限不会转为公开访问。已有能力只补测试，不重复开发。 |
| M2-02 | 增加可撤销删除的最小方案。 | 优先在 Thing 中增加删除状态，不另建第二套笔记模型。删除后从普通列表、标签使用量、搜索、RSS、公开链接中排除；恢复默认不自动恢复公开权限。此项属于产品契约变更，须先确认规则。 |
| M2-03 | 明确附件与删除生命周期。 | 回收区引用、刚上传未绑定以及编辑中的附件均受保护；先只读盘点，永久删除需重新核对引用并处理并发。未完成此前禁用会误删这些附件的既有清理路径；不上 TTL 或新 Worker。 |
| M2-04 | 选择性增加浏览器草稿持久化。 | 与用户身份、笔记 ID、基准 revision 绑定；明确开关、过期和退出清理；共享设备不得跨用户显示草稿。不把它扩展为离线多端同步系统。 |
| M2-05 | 退役真正无调用者的迁移投影与兼容代码。 | 先检查 readiness、历史迁移、回滚与备份工具的依赖；满足退出条件后才删除 tags projection 或兼容适配。迁移已删除的用户仓库不重复列为任务。 |

不可为了删代码而破坏恢复。write-freeze 只在仍有迁移或灾难敏感维护需求时保留，不向普通业务添加租约、全局锁或计数器。若依赖尚未退役，记录保留原因和删除条件，不强删。[M1]

M2-02/03 是同一生命周期交付：删除过滤不仅覆盖列表，还要覆盖详情、文件访问、公开分享、RSS、标签聚合、搜索及用户导入导出；灾备必须保留回收区数据。`deletedAt` 是安全相关读取规则，不是“加字段所以自然向后兼容”。旧镜像若不认识该状态，可能重新显示已删内容；未经兼容验证禁止带访问流量回退。恢复必须先证明公开/分享标记已清除，再让对象可见。

M2-01 稳定链接和 M2-05 历史模块退役可独立验收；M2-04 浏览器持久草稿为可选项，不阻塞检索或其他基础可靠性任务。持久草稿含私人内容，必须明确开关、到期及退出清理；不承诺浏览器存储具备加密保险箱能力。

**退出门槛：** 已批准的子任务逐项验收。若实施可撤销删除，读取/授权/附件/恢复/回退必须联合通过，不能仅凭删除按钮通过就发布。历史依赖尚未退出时可以保留，不阻塞 M3 的只读基线。

## 7. M3：先证明“找得到”，再选择搜索技术

**目标：提高中文笔记、标签、链接与长期资料的找回质量。**

先建立小而固定的相关性样本，例如 30–50 个经过脱敏或合成的查询，包含中文词语、精确短语、标签、链接和混合文本，并记录预期命中的笔记。记录当前命中表现、查询时延、样本规模和资源配置，不因为已经有 `$text` 就把中文找回质量视为已验证。

优先改进现有 MongoDB 查询、索引、分页和界面过滤。保持 URL 对筛选状态的所有权；在固定数据集下验证分页不遗漏、不重复，对并发修改导致列表变动的行为给出明确说明。只有发现实际问题时才调整分页方式，不预先承诺跨多次请求的一致快照。

| 编号 | 任务 | 门槛 |
| --- | --- | --- |
| M3-01 | 建立相关性与性能基线，复用已有 benchmark 入口。 | 可重复比较，同一环境与数据集，不用主观演示替代结果。 |
| M3-02 | 优化现有查询和读取负担。 | 精确查询不退化，owner 隔离始终成立；任何缓存都有键、上限和失效规则。 |
| M3-03 | 稳定引用与搜索结果跳转联合验收。 | 搜到之后能正确打开、回退和继续浏览，不仅返回数据库命中。 |

**退出门槛：** 找回质量达到已约定目标，性能基线稳定。只有当剩余问题确实是语义缺口、而不是索引或前端错误时，才进入 M4。

## 8. M4：条件式 AI 增强

顺序为：可选查询改写/结果重排 → 有明确来源的只读问答 → 需要时再评估 embedding。第一步只接一个 Provider、一个小适配接口，不先建多模型路由或 Agent 平台。[M1]

所有结果以 `thingId + sourceRevision + model/version + generatedAt` 等来源信息绑定原文版本。原文更新或用户权限变化后，旧派生结果必须失效或重新校验。未经用户采纳不得覆盖 content、标签或标题。

对外发送哪些查询或笔记片段必须明确并由用户选择；密钥、会话、私有附件路径不进入模型提示、客户端或日志。默认测试使用 fake transport；真实调用和费用另行授权。关闭 AI 后 CRUD、传统搜索、标签、分享、附件、导入导出、备份恢复仍完整可用。

**启动条件：** 核心读写/授权/隔离测试可用，M1 已完成；M3 基线证明确有语义缺口；能限定发送范围并用固定样本验证价值。M2 中可选回收站、浏览器持久草稿或历史代码删除不是只读 AI 试验的无关前置。没有增益就停止。embedding 只有在试验证明必要时才评估，仍为可重建投影。

## 11. 跨项目工程契约（两份路线图共同约束）

本节在两份文件中保持一致，仅是一页级接口约定，不新建公共运行库或治理服务；未来更新须同步双方文本。操作责任按“谁的资源、谁批准”划分，不由编码 Agent 推断授权。

| 对象/动作 | 责任与操作范围 | 必须验证的边界 |
| --- | --- | --- |
| Meemo Web、`meemo` 库、私有附件 | Meemo 任务负责本项目代码；生产操作单独授权 | Web 重启不等于停共享 DB；库级备份/恢复不触及 travel_cards。 |
| travel-cards Web、`travel_cards` 库、专用 R2 对象 | travel-cards 任务负责本项目代码；远端字节操作单独授权 | 启停 Web 不管理共享 DB/卷；不使用共用备份 bucket 做清理。 |
| 共享 MongoDB 实例、认证、网络、数据卷 | 延续现有 Meemo 部署的生命周期归属；由维护者协调两应用 | 认证切换/升级/实例重建单独成任务，双应用可读写、备份账号权限和回退都须验证。 |
| 独立应用备份 | 只冻结本应用全部写者并排空，另一应用可继续使用其库 | 两项目无跨库业务事务，不强求一个全局快照；实际共享资源变更才联合停写。 |
| 整实例/卷恢复 | 两应用协同授权、停写与恢复 | 不能拿单应用备份当整实例灾备；不能用一次泛化 `--drop` 或 `down -v` 冒充分库恢复。 |

**配置与资源身份。** 实施前记录真实 Compose project、网络、MongoDB 实例和卷名称/标识以及逻辑数据库。参数化、目录改名或新默认值不得静默创建另一空库/空卷。缺少预期共享资源应失败并提示，不自动创建一个“看起来能启动”的替代品。普通 Web 发布不迁移数据库所有权。

**测试隔离。** 默认测试运行器创建带随机 run 标识的临时实例、数据库及存储目录。清理前同时核对资源标签/实例身份、精确库名、当前 run 标识；仅以库名含 `_test`、host 为 localhost 或设置 NODE_ENV=test 均不充分。禁止连接生产共享实例执行默认测试。采用已有测试实例时须具有独立身份和独立授权，不能以“不同库名”为由借用生产实例。清理仅删除本次创建的资源，不用全局 prune；失败也保留脱敏诊断且不误删其他运行的测试资源。

**恢复隔离。** 在一次性实例或严格核验的目标库中恢复；namespace allowlist、必要的重命名映射和命令参数按实际数据库工具版本验证。另设一份模拟另一应用的哨兵数据，前后内容/索引不变才算通过。生产恢复审批同时说明恢复点之后的合法写入如何处理，不能用数据丢失来掩盖代码回退失败。

**证据与秘密。** 一个任务回执只需 SHA、实际命令、工具版本、用例结果、隔离资源标识、相关哈希、未执行项和回退判断。证据留在授权的私有工作目录；Git 只保留脱敏结论与模板。环境变量原文、数据库 URI 密码、Token、用户正文、私有附件和未净化 inspect/Compose 输出不得作为公开日志。示例环境文件只有非生产占位值。

**实施与授权。** 两项目代码可独立推进，不互相等待完整路线结束；仅共享实例变更需要真正协同。新增存储字段、权限/可见性和公开 API 行为要先修订本项目权威契约。共享数据库不意味着共用认证 Cookie、集合、业务模型或自动公开 Meemo 内容；不做自动双向同步。
